# الكتالوج المعرفي للمهارات الهندسية — نموذج توظيف الذكاء الاصطناعي في الهندسة البرمجية

> وثيقة مرجعية أكاديمية موثّقة تعرض منظومة متكاملة من **المهارات** (Skills) كمكوّنات معرفية قابلة للاستدعاء، تُمكّن العامل الذكي (AI Agent) من أداء مهام هندسية متخصصة بدقة قابلة للقياس، وأدلة موثّقة، وحوكمة صارمة.

| | |
|---|---|
| **غرض الوثيقة** | توثيق بنية الكتالوج، منهجية التشغيل، المنظومات المترابطة، وأوامر التفعيل لتعظيم كفاءة أداء الذكاء الاصطناعي |
| **الفرع المستضيف** | `BI` (فرع ذكاء الأعمال — Business Intelligence) |
| **تصنيف المحتوى** | 17 مجالاً معرفياً | 116 مهارة موثّقة | مراجع وأوامر ونصوص تشغيل |
| **اللغة** | العربية (مع مصطلحات تقنية إنجليزية للمطابقة) |

## 1. الإطار النظري: ما هي "المهارة" في سياق الذكاء الاصطناعي؟

تُعرَّف **المهارة** في هذا النموذج بأنها **وحدة مستقلة من المعرفة الإجرائية** تُغذّي الذاكرة المؤقتة للعامل الذكي قبل تنفيذ عمل ما. لا تُنفَّذ المهارة ذاتياً؛ بل تُستدعى عند تطابق "المشغّل" (Trigger) مع نية المستخدم، فتمنح النموذج:

1. **سياق القرار**: متى تُستخدم هذه المهارة؟ ومتى يُمنَع استخدامها؟
2. **بروتوكول التنفيذ**: خطوات إجرائية محددة ومرتبة.
3. **الحدود الصارمة**: نطاق مُحكم لا يُتجاوز دون موافقة بشرية.
4. **المخرجات الثابتة**: قوالب، مخططات، أو نصوص برمجية حتمية النتائج.

وهذا يحوّل سلوك النموذج من "التوليد الحرّ الاحتمالي" إلى "تنفيذ منضبط موثّق" — جوهر الكفاءة الهندسية.

### 1.1 تشريح المهارة الواحدة (البنية الداخلية)

| المكوّن | الوظيفة المعرفية |
|---|---|
| `SKILL.md` | الوثيقة التنفيذية: تحتوي على عيّنات البيانات الوصفية (`name`, `description`) التي يستعملها نظام التوجيه لاختيار المهارة، ثم تعليمات سير العمل الكاملة. |
| `references/` | قاعدة معرفية مرافقة: تفاصيل تقنية، نمطية، وقوالب حسب النطاق (يُستحضر عند الحاجة لا عند الاستدعاء). |
| `scripts/` | نصوص حتمية قابلة للتنفيذ تُشغَّل خطوةً خطوة لضمان نتائج مستقلة عن تقلّب النموذج. |
| `assets/` | أصول جاهزة: نماذج إدخال، نماذج مخرجات، قوالب مرجعية تُستخدم للتحقق والمقارنة. |
| `agents/` | تعريفات واجهات إضافية (منظومة خارجية اختيارية). |

> **مبدأ الكفاءة**: فصل المعرفة (references) عن التنفيذ (scripts) عن الحوكمة (SKILL.md) يقلل استهلاك النماذج العالية التكلفة ويجعل كل مهارة **اقتصادية** و**قابلة للتحقق**.

## 3. منهجية التشغيل: كيف يعمل العامل الذكي مع المهارة؟

تُسير دورة الاستدعاء وفق مسار من أربع مراحل:

```
النية → المطابقة → الاستدعاء → التنفيذ → المخرجات الموثقة
   │         │            │           └── أدلة + تحقق
   │         │            └── تحميل SKILL.md + references عند الحاجة
   │         └── مطابقة "وصف المهارة" مع عبارة المستخدم (Trigger)
   └── تحويل الطلب الطبيعي إلى طلب هندسي محدد
```

1. **التحوّل الدلالي**: يُترجم طلب المستخدم اللغوي إلى نية هندسية واضحة.
2. **المطابقة المعرفية**: يُقارن الوصف (description) في عيّنات كل `SKILL.md` مع النية؛ وهذا يعزّز "انتقائية" المهارة ويقلل الاستدعاءات الخاطئة.
3. **الاستدعاء والتنفيذ**: يُحمَّل ملف التشغيل وسير العمل، وتُستثمر `scripts/` في الخطوات الحتمية.
4. **التوثيق والتحقق**: تُسجَّل الأدلة (لقطات، سجلات، مخرجات) في مساحات موحّدة كشرط للإغلاق.

> **أثر على الكفاءة**: اختيار مهارة دقيقة واحدة بدل التوليد الحرّ يرفع دقة النتيجة و يخفض التكرار ويجعل الفشل قابلاً للتشخيص.

## 4. المنظومات المترابطة: ديناميكا التعاون بين المهارات

أقوى ما في هذا الكتالوج ليس الفرد بل **القوافل المتعاضدة**؛ فالمهارات تُصمَّم لتتدفق من مدخل إلى مخرج عبر تسلسلات محددة. فيما يلي أهم **المنظومات السبْع** وما يُنتج كلٌّ منها:

### 4.1 منظومة التحليل → الإصلاح → الاستقرار
```
system-diagnostics → change-impact-mapper → regression-guard → defect-fixer / stability-hardener → إعادة التحقق
```
**المنطق**: الشخوص قبل العلاج. تُشخَّص الأعطال بأدلة، ويُحدَّد نطاق الانفجار، ثم يُصلَح ضمن نطاق محكم قبل التحقق من عدم الانحدار. تستثمر هذه القافلة أدوات CI (`ci-failure-analyzer`, `gh-fix-ci`) والتحقيق في الحوادث (`incident-investigator`) كمدخلات.

### 4.2 منظومة الدفاع الأمني
```
security-gate → security-ownership-map → security-threat-model → security-best-practices → security-remediator
```
**المنطق**: من الفرز (triage) إلى الملكية (ownership) إلى النمذجة (threat model) إلى الوقاية (best practices) ثم المعالجة المنضبطة (remediation) مع فحوص أثر قبل التعديل.

### 4.3 منظومة دورة الحياة SDLC
```
sdlc-requirements-guru → sdlc-ba → sdlc-arch → sdlc-dev → sdlc-qa → sdlc-devops
مع إدارة: sdlc-pm-product | sdlc-pm-project | والتنسيق الكلي: sdlc-orchestrator
```
**المنطق**: مدخلات (الاحتياجات) ← تحويل (BA) ← تصميم (Arch) ← بناء (Dev) ← تحقق (QA) ← نشر (DevOps)، مع طبقة إدارية وتنظيمية شاملة تضبط بوابات المراحل وتتبّع التسليم.

### 4.4 منظومة التصميم البصري Figma
```
figma-use (شرط مسبق إلزامي) → figma-generate-design / figma-generate-library → figma-implement-design → figma-code-connect-components
```
**المنطق**: التأسيس قبل التنفيذ. لا يُستدعى أي أمر كتابة في Figma دون تحميل `figma-use`؛ ثم يُبنى التصميم أو النظام، ويُترجم إلى كود بمطابقة 1:1، ويُربط مكوّناً-بمكوّن.

### 4.5 منظومة اختبار الواجهات الرسومية (GUI)
```
gui-test-orchestrator → gui-test-data-sandbox → pyqt-test-engine / desktop-e2e-automation
→ gui-failure-recorder → gui-flake-stabilizer → gui-repair-runner → gui-visual-regression
```
**المنطق**: تخطيط، ثم عزلة بيانات، ثم تنفيذ آلي، ثم توثيق كل فشل، ثم تثبيت الاهتزاز، ثم إصلاح وإعادة اختبار، ثم إثبات بصري بعدم وجود انحدار.

### 4.6 منظومة ذكاء المستودع وصنع القرار
```
codebase-intelligence → architecture-guardian → dependency-governor → performance-auditor → future-risk-forecast → project-operations-ledger
```
**المنطق**: الفهم الكامل (Intelligence) يغذّي تقييم المعمارية والتبعيات والأداء، ثم التنبؤ بالمخاطر المستقبلية، مع ذاكرة تشغيلية دائمة (Ledger) تحفظ القرارات والأحداث.

### 4.7 منظومة التسليم والنشر والإصدار
```
docs-automation → evidence-sync → delivery-sync → release-manager
بالاشتراك مع: 08-deployment (Cloudflare / Netlify / Render / Vercel)
```
**المنطق**: توثيق محدّث ← أدلة مجمّعة في حزمة واحدة ← مزامنة مع أنظمة التتبع ← خطة إصدار مع جاهزية استرجاع ← نشر فعلي على المنصة المناسبة.

### 4.8 منظومة حوكمة المهارات (الاستدعاء في الكتالوج)
```
skill-forge-master → skill-quality-auditor → skill-change-impact-analyzer → skill-update-governor → skill-knowledge-updater → skill-registry-manager
```
**المنطق**: البناء الجيد، ثم القياس، ثم تحليل الأثر قبل أي تعديل، ثم قرار الموافقة، ثم تحديث المعرفة من مصادر رسمية، ثم الحفاظ على السجل والظهور.

> **قاعدة عملية**: عند مواجهة مهمة متعددة الأوجه، يُفضَّل تفكيكها إلى مراحل وتفعيل مهارات كل مرحلة بالتتابع بدل استدعاء مهارة واحدة شاملة — فيزداد الوضوح وتنخفض نسبة الخطأ.

## 6. استراتيجيات تعظيم كفاءة أداء الذكاء الاصطناعي

بناءً على تصميم الكتالوج، تُرفع الكفاءة عبر الاعتماد على المبادئ الآتية:

1. **دقة المشغّل قبل التنفيذ**: صياغة العبارة بذكر المجال والحدود (مثال: "راجع أمان هذا المكوّن **فقط**") يقلل التفسير الحرّ ويوجّه المطابقة.
2. **الالتزام بالشروط المسبقة**: كقاعدة `figma-use` الإلزامية — تجاهلها ينتج فشلاً شائعاً قابلاً للتصنيف؛ لذا تحفظ الظروف المسبقة داخل كل مهارة.
3. **التسلسل المدعم بالأدلة**: لا إصلاح قبل تشخيص، ولا تعديل قبل خريطة أثر، ولا إغلاق دون تحقق. ترتيب القوافل في القسم (4) ليس استشعاراً بل دورة إلزامية للجودة.
4. **عزل التجارب عن الإنتاج**: استخدام `gui-test-data-sandbox` وأدوات العزل يمنع تلويث البيانات الحقيقية ويجعل التكرار آمناً.
5. **الأرشفة الموحّدة للأدلة**: مساحات مثل `.codex-project-intel/` (عبر `project-operations-ledger` و`evidence-sync`) تجعل أي ادعاء بالنجاح قابلاً للإثبات وإعادة الفحص.
6. **الحوكمة عند التعديل الذاتي**: تعديل المهارات نفسها يمرّ عبر بوابات `skill-change-impact-analyzer` و`skill-update-governor` — فالنظام يحرس حدوده.
7. **استثمار النصوص الحتمية**: عند وجود `scripts/` تُستثمر في العمليات المتكررة كخبزٍ محسوب بدل الاعتماد على الحساب الاحتمالي للنموذج.
8. **الفصل بين اللغة وسير العمل**: اعتماد لغة واجهة موحّدة (كالعربية للتسليم وطلبات الترجمة، عبر `cityofaiagents-translation-ops`) يضمن تتبع الطلبات ثنائي اللغة دون فقدان الدلالة.

## 7. دليل الاستخدام العملي

### 7.1 للباحث/المطوّر
- تصفّح المجلدات الستة عشر وفق القسم (2) واختر المجال الذي يطابق المهمة.
- افتح `SKILL.md` للمهارة المقصودة: ستجد "متى تُستخدم" و"سير العمل" و"القيود".
- عند الحاجة لتفاصيل تنفيذية: تابع إلى `references/` و`assets/` في نفس المهارة.

### 7.2 للعامل الذكي
1. اقرأ `description` في كل مهارة مرشّحة للمطابقة.
2. التزم بأي أمر تشغيل محدد (كالأمر المسبق أو صيغة سطر أوامر) قبل التنفيذ.
3. نفّذ الخطوات بالتسلسل، واستثمر `scripts/` للخطوات الحتمية.
4. أخرج الأدلة وسجّلها قبل إعلان الاكتمال.

### 7.3 لنشر/مزامنة الكتالوج
- الكتالوج يعمل مباشرة من هذا المستودع على الفرع `BI`.
- يمكن تثبيت المهارات في بيئة أي عامل ذكي عبر أدوات التثبيت (`skill-installer` أو نسخ المجلد) ثم إعادة الفحص عبر `skill-registry-manager`.
