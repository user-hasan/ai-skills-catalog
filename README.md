# كتالوج المهارات — ai-skills-catalog

مستودع منظّم يضم **جميع مهارات الذكاء الاصطناعي** (Skills) الموجودة في مساحة العمل `E:\mySkills\skills`، مصنفة إلى **16 فئة** وفقاً لمجال عملها. كل مهارة مدعومة بملف `SKILL.md` يشرح متى تُستخدم وكيف تعمل، مع ملفات مرجعية (`references/`) وأصول (`assets/`) عند الحاجة.

> **الفرع:** `BI` — جميع محتويات هذا الكتالوج موجودة في فرع ذكاء الأعمال (Business Intelligence).
> **المصدر:** منطقة المهارات الأصلية خارج المستودع | **تاريخ الإنشاء:** 2026-09-02

---

## لماذا هذا المستودع؟

- **ترتيب وتصنيف** عشرات المهارات المبعثرة في مجلدات واضحة حسب الوظيفة.
- **توثيق** عمل كل مهارة بشرح عربي مختصر في مكان واحد.
- **نسخ آمن** من المهارات المعتمدة لفريقك/مستودعاتك دون المساس بالأصل.

## كيف تُستخدم المهارات

- كل مجلد فرعي داخل فئة هو مهارة مستقلة تبدأ بملف `SKILL.md`.
- قرأ العامل الذكي (Codex/opencode) ملف `SKILL.md` ليعرف متى يُفعّل المهارة وكيف ينفّذ سير عملها.
- المراجع داخل `references/` والملفات القابلة للتنفيذ داخل `scripts/` تخدم المهارة عند الطلب.

# فهرس المهارات وشرح عملها

## 01-sdlc — دورة حياة تطوير البرمجيات وإدارة المشاريع

| المهارة | شرح العمل |
|---|---|
| **sdlc-orchestrator** | الإشراف على دورة حياة تطوير البرمجيات كاملة: تنسيق المراحل، التحقق من المخرجات، منع عبور المراحل قبل نضجها، ومتابعة التقدم مع تقارير موحدة لكل الأدوار. |
| **sdlc-arch** | هندسة البرمجيات: اختيار الأنماط المعمارية، مقارنة البدائل، توليد سجلات القرارات (ADR)، وضمان تلبية متطلبات الأمان وقابلية التوسع قبل البناء. |
| **sdlc-ba** | تحليل الأعمال: توليد قصص المستخدم، صياغة معايير القبول، رسم خرائط العمليات، تحليل الفجوات، وتوثيق قواعد العمل. |
| **sdlc-dev** | التطوير: هيكلة المشاريع، تطبيق معايير الكود، دعم مراجعة الكود، توليد اختبارات الوحدة، وتوثيق الواجهات البرمجية. |
| **sdlc-devops** | عمليات التطوير والنشر: خطوط CI/CD، البنية التحتية ككود، المراقبة، إدارة الأسرار، فحص الأمان، وجاهزية الاسترجاع. |
| **sdlc-pm-product** | إدارة المنتج: كتابة وثائق المتطلبات (PRD)، تحديد نطاق MVP، ترتيب أولويات التراكم، خطط OKR، وتحليل السوق. |
| **sdlc-pm-project** | إدارة المشروع: تخطيط السباقات، توزيع العمل، تتبع السرعة، إدارة المخاطر، وتقارير الحالة لأصحاب المصلحة. |
| **sdlc-qa** | ضمان الجودة: تخطيط الاختبارات، تصميم حالات الاختبار، تجهيز الأتمتة، فحوص الأداء، تحليل الانحدار، وتوثيق العيوب. |
| **sdlc-requirements-guru** | استكشاف المتطلبات: كشف الغموض وتحديد النطاق، استبيانات الاكتشاف، فحوص الجاهزية، وتقييم المخاطر قبل التخطيط والبناء. |
| **meeting-to-backlog** | تحويل محاضر الاجتماعات وملاحظات الورش إلى عناصر تراكم أعمال قابلة للتنفيذ مع القرارات والمخاطر والأدوار المعلنة. |
| **repo-intake-triage** | فرز الطلبات الواردة (Issues وPull Requests وتقارير الأخطاء والطلبات المميزة): فحص الجاهزية، رصد السياق الناقص، اقتراح التسميات، وتوجيه التسليم. |

## 03-diagnostics-repair — التشخيص والإصلاح واستقرار الأنظمة

|---|---|
| **system-diagnostics** | اكتشاف فشل البناء، فشل الاختبارات، الاستيرادات المكسورة، ونقص إعدادات التشغيل مع أدلة دائمة تحت `.codex-project-intel/diagnostics/`. |
| **ci-failure-analyzer** | تحليل سجلات CI وGitHub Actions: تصنيف الوظائف الفاشلة، استخراج الأوامر المخفقة، وكشف الإخفاقات المتقلبة أو البيئية قبل الإصلاح. |
| **incident-investigator** | التحقيق في الحوادث الإنتاجية وبرامج التعطل وسجلات Sentry؛ الفصل بين الأعراض والمسبب والسبب الجذري وفجوات التحقق. |
| **defect-fixer** | تحويل نتائج التحليل إلى خطط إصلاح محدودة النطاق وتطبيق تعديلات ملفات مؤكدة داخل نطاق موافَق عليه ومراجَع بشرياً. |

| **regression-guard** | رسم خريطة نطاق الانفجار ومتطلبات التحقق قبل كل إصلاح لتحديد ما قد ينكسر في المسارات الساخنة. |

| **change-impact-mapper** | رسم خريطة أثر أي تغيير مقترح (كود، تبعيات، أمان، ترحيل، إعادة هيكلة) لتحديد الملفات والاختبارات المتأثرة قبل البدء. |
