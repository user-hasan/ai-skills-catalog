# 17-agent-workflows — منهجيات سير عمل العامل الذكي

> مهارات تحوّل طريقة عمل العامل الذكي نفسه: مناهج إلزامية للتفكير قبل التصميم، والتخطيط قبل التنفيذ، والاختبار قبل الكود، والتصحيح المنهجي، والتحقق قبل الإعلان عن الاكتمال، وأدب مراجعة الكود، وعزل العمل عبر Worktrees.

## المهارات في هذه الفئة

| المهارة | شرح العمل |
|---|---|
| **using-superpowers** | نقطة الانطلاق لأي جلسة: يؤسس منهجية إيجاد المهارات واستدعائها عبر أداة Skill قبل أي استجابة (بما فيها أسئلة التوضيح). |
| **brainstorming** | شرط إلزامي قبل أي عمل إبداعي (ميزة، مكوّن، تعديل سلوك): يستكشف نية المستخدم ومتطلباته وتصميمه قبل تحديد أي تنفيذ. |
| **writing-plans** | تحويل مواصفة أو متطلبات مهمة متعددة الخطوات إلى خطة تنفيذ مكتوبة قبل لمس الكود. |
| **executing-plans** | تنفيذ خطة مكتوبة في جلسة منفصلة مع نقاط مراجعة ومحطات توقف للتحقق. |
| **subagent-driven-development** | تنفيذ الخطط بتفويض كل مهمة مستقلة إلى وكيل فرعي، مع مراجعة الكود بين المهام في الجلسة نفسها. |
| **dispatching-parallel-agents** | تفويض مهمتين مستقلتين أو أكثر (بلا حالة مشتركة أو تبعيات تسلسلية) إلى وكلاء يعملون بالتوازي لرفع السرعة. |
| **test-driven-development** | تطوير قائم على الاختبار أولاً: كتابة اختبار صغير، مشاهدته يفشل، كتابة الحد الأدنى من الكود لإنجاحه، ثم إعادة الهيكلة. |
| **systematic-debugging** | منهجية تصحيح صارمة عند أي خطأ أو فشل اختبار أو سلوك غير متوقع: فهم السبب الجذري قبل اقتراح أي إصلاح. |
| **verification-before-completion** | شرط الإغلاق: تشغيل أوامر التحقق الفعلية وتأكيد مخرجاتها قبل أي ادعاء بنجاح أو اكتمال؛ الأدلة قبل التأكيدات دائماً. |
| **receiving-code-review** | تعليم فن استقبال ملاحظات المراجعة بصرامة تقنية: تحقق وعدم موافقة شكلية، خاصةً إذا كانت الملاحظة غامضة أو مشكوكاً فيها. |
| **requesting-code-review** | متى يُطلب طلب مراجعة الكود (عند إتمام المهام أو قبل الدمج) للتحقق من مطابقة العمل للمتطلبات. |
| **finishing-a-development-branch** | إغلاق فرع تطوير مكتمل الاختبارات: تقديم خيارات منظمة للدمج أو الـ Pull Request أو التنظيف. |
| **using-git-worktrees** | عزل العمل الجديد عن مساحة العمل الحالية عبر Git Worktrees مع اختيار ذكي للمجلدات وفحص الأمان قبل البدء. |
| **writing-skills** | إنشاء مهارات جديدة أو تحرير القائمة أو التحقق من صحتها قبل نشرها للتشغيل. |

---

## منظومة التعاون الداخلية لهذه المجموعة

```
brainstorming → writing-plans → executing-plans / subagent-driven-development
      → (أثناء التنفيذ) test-driven-development + systematic-debugging
      → verification-before-completion → requesting-code-review → receiving-code-review → finishing-a-development-branch
```

ولهذه المنظومة أدوات عزل وتنظيم: `using-git-worktrees`، وأساس استدعائها كله `using-superpowers` و`writing-skills` لضمان سلامة النظام نفسه.
